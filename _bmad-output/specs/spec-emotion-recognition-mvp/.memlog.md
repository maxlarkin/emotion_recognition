- (direction) User: screens = live webcam video with face boxes + emotion labels; upload recorded video for analysis; export results; no auth in MVP.
- (direction) User: acceptance = end-to-end latency <1 s; demo = start app, enable camera, see own video with small delay and recognized emotions.
- (direction) User: run via Docker; Linux + Windows; local deploy; fully offline. Architecture and story order delegated to Claude.
- (constraint) Hardware: laptop, NVIDIA GPU 4 GB VRAM, 16 GB RAM; no GPU server; must also run CPU-only (Docker GPU passthrough may be unavailable).
- (constraint) Timeline 1.5 months to MVP. Educational project: model licenses (incl. non-commercial) acceptable.
- (constraint) Stack fixed: FastAPI backend, React frontend.
- (decision) Models (from research): YuNet face detector + EmotiEffLib enet_b0_8_va_mtl ONNX for FER; Silero VAD + GigaAM-Emo for Russian SER; no fine-tuning in MVP.
- (decision) Emotion set shown = 7 basic: anger, disgust, fear, happiness, sadness, surprise, neutral. FER 8-class contempt dropped and probabilities renormalised. Audio 4 classes (angry, sad, neutral, positive) map to anger, sadness, neutral, happiness.
- (decision) Fusion = weighted late fusion on shared classes + temporal smoothing per tracked face; audio weight 0 when VAD finds no speech; weights configurable.
- (decision) Webcam+mic captured in browser (getUserMedia), not in container: avoids device passthrough on Windows Docker; localhost is a secure context.
- (decision) Transport live = one WebSocket: client sends JPEG frames 5-10 fps + PCM16 16 kHz mono chunks; server returns per-frame JSON results; latest-frame-only slot, stale frames dropped.
- (decision) Inference runs in separate worker process(es) from the FastAPI event loop; source -> queue -> worker -> result bus seam so RTSP/multi-camera sources can be added later without rewrite.
- (decision) Docker: docker compose with 2 services (frontend static build via nginx, backend FastAPI+inference). GPU profile uses NVIDIA runtime; default profile CPU-only. Model weights baked into backend image at build time.
- (decision) Persistence: SQLite + files in a named Docker volume; sessions (live and file) store per-frame/per-window results for export.
- (decision) Export formats: CSV and JSON timelines per session (timestamp, face track id, box, per-emotion probs, fused label, audio label).
- (decision) Latency metric: client-side, from frame capture timestamp to rendering of that frame's overlay; p95 < 1000 ms over a 60 s session on target laptop (GPU profile).
- (decision) File analysis: upload common containers (mp4/webm/mkv/avi); backend decodes with ffmpeg; analyses video at 5 fps and audio in 2-5 s windows; progress shown; result viewable as player with overlay + timeline.
- (decision) Deliverables beyond code: media quality regulation document (seeded from research 4.2) and scaling justification document for 20+ cameras (seeded from research 3.3-3.4).
- (decision) Add offline evaluation script reporting UAR / macro-F1 on public test subsets (e.g. RAF-DB / RESD / Dusha samples) to back the regulation document; no accuracy target for MVP.
- (assumption) Offline means runtime offline; images are built once with internet (or loaded via docker save/load) - build-time downloads allowed.
- (assumption) Single user, single live session at a time is sufficient for MVP.
- (assumption) Annotated MP4 export (burned-in overlay) not required; CSV/JSON export satisfies 'export'.
