# EmoSense — спецификация интерфейса

Веб-интерфейс системы, которая анализирует видео с камер в клиентских точках, находит эпизоды негативных эмоций у клиентов и уведомляет ответственного человека. Второй сценарий: пользователь загружает готовую запись и получает результат распознавания.

Визуальный эталон — файлы в `mockups/`. Токены — `tokens.json` / `tokens.css`. API — `API.md`.

---

## 1. Общие принципы

- **Тема** тёмная: фоны тёмно-синие и серые, текст и иконки белые.
- **Стиль** плоский. Углы острые (`border-radius: 0`). Исключение — круглые точки статуса.
- **Тени** только у выпадающих меню и активных / раскрытых элементов (`--shadow-dropdown`, `--shadow-active`).
- **Шрифты:** IBM Plex Sans для текста, IBM Plex Mono для чисел, времени, разрешений и адресов.
- **Минимализм.** Без поясняющих подписей, если смысл ясен из заголовка. Каждая настройка — отдельная строка.
- **Плотность.** Элементы занимают почти всю ширину. Внешние отступы 12 px, промежутки между блоками 8–12 px.
- **Язык** интерфейса — русский. Десятичный разделитель — запятая (`0,91`), проценты через пробел (`72 %`).
- **Адаптивность.** При ширине меньше ~900 px боковая колонка уходит над контентом, тулбар переносится, таблицы прокручиваются горизонтально внутри своего блока.
- **Доступность.** Настоящие `<button>`, `<a>`, `<input>` + `<label>`. У иконок-кнопок `aria-label`. Видимый фокус. `aria-expanded` у раскрывающихся элементов, `aria-pressed` у переключателей.

## 2. Карта экранов

| Экран | Файл макета | Маршрут (предложение) |
|---|---|---|
| Потоки: список пуст | `mockups/Empty.dc.html` | `/streams` (нет потоков) |
| Потоки: список и выбранный поток | `mockups/Main.dc.html` | `/streams/:streamId` |
| Настройки | `mockups/Settings.dc.html` | `/settings/:tab` (`notify`, `recipients`, `cameras`, `log`) |
| Анализ видео | `mockups/Analyze.dc.html` | `/analyze/:fileId?` |

### Переходы

- Логотип → `/streams`.
- Шестерёнка у потока в списке → `/settings/cameras` с раскрытой камерой этого потока (`?camera=:id`).
- «Настройки камеры» в блоке «Камера и обработка» → то же самое.
- Пункты меню «Настройки» → соответствующая вкладка.
- Пункты меню «Анализ видео» → `/analyze`.
- Клик по уведомлению в колокольчике → `/streams/:streamId` этого инцидента.
- «Добавить поток» (пустое состояние, кнопка «+» в списке, пункт меню) → модальное окно добавления потока. Его в макете нет, см. §9.

## 3. Компоненты

### 3.1 Тулбар (на всех экранах)
- Закреплён сверху (`position: sticky`), высота 44 px, фон `--bg-toolbar`, нижняя граница `--border`.
- Слева логотип: иконка 22 px в цвете акцента и «EmoSense» (16 px, 600).
- Меню из четырёх кнопок высотой 36 px, у каждой текст и шеврон.
- Справа, только на экране потоков, колокольчик уведомлений 34×34 со счётчиком новых.

**Меню (выпадающее по клику, аналог ленты):**

| Кнопка | Пункты |
|---|---|
| Потоки | Добавить поток · Управление потоками |
| История | Журнал · Инциденты · Экспорт |
| Настройки | Уведомления · Получатели · Камеры · Журнал и данные |
| Анализ видео | Загрузить запись · Результаты |

**Поведение:**
- Клик по кнопке открывает её меню. Повторный клик закрывает.
- Клик по другой кнопке переключает на её меню.
- Клик вне меню закрывает его. В макете для этого под меню лежит прозрачная кнопка на весь экран; в реализации лучше click-outside + Esc.
- Пункт меню выполняет действие и закрывает меню.
- **Открытое меню:** фон `--bg-dropdown`, рамка `--border-strong`, `--shadow-dropdown`, пункты высотой 40 px, наведение `--bg-dropdown-item-hover`.
- **Кнопка с открытым меню:** фон `--bg-dropdown`, рамка, `--shadow-active`.

### 3.2 Колокольчик уведомлений
- Счётчик — оранжевый квадрат 16×16, показывается, пока есть неподтверждённые инциденты.
- Выпадающий список шириной 300 px. Элемент списка:
  - точка (оранжевая — новое, серая — обработанное);
  - «Точка · Камера · #трек»;
  - вторая строка: «ЧЧ:ММ:СС · новое / подтверждено / ложное».

### 3.3 Карточка потока (список слева)
- Строка с двумя зонами:
  - кнопка выбора: название, затем строка со статусом (точка + «В эфире / Подключение / Нет сигнала») и меткой «Инцидент», если он есть;
  - справа ссылка-шестерёнка 44 px с левым разделителем.
- **Активная:** фон `--bg-active`, рамка акцента, `inset 3px 0 0 accent`, `--shadow-active`.
- **С неподтверждённым инцидентом:** рамка `--alert-soft-border`.
- Потоки сгруппированы по точкам: заголовок группы — капслок, 12 px, `--text-muted`.

### 3.4 Плашка инцидента
- Высота 32 px, фон `--alert-panel-bg`, рамка `--alert-bg`.
- Состав: иконка-треугольник, текст «Клиент #12 · негатив 0,91 · 1:20» (обрезается многоточием), кнопки высотой 24 px:
  - **«Подтвердить»** (залитая): отмечает инцидент подтверждённым, скрывает плашку, снимает счётчик;
  - **«Ложное»**: отмечает ложным (это сигнал для калибровки порога), скрывает плашку, снимает счётчик;
  - **«Скрыть»**: прячет плашку только на этом экране. Инцидент остаётся неподтверждённым в колокольчике.

### 3.5 Плитка-показатель
- Одна строка: подпись слева (12 px, `--text-secondary`), значение справа (17 px, 600). Внутренние отступы 6×12 px.
- Плитка «Статус» при инциденте: фон `--alert-panel-bg`, рамка `--alert-bg`.

### 3.6 Метка статуса (chip)
| Код | Текст | Цвета |
|---|---|---|
| `alert` | Инцидент | `--alert-bg` / `--alert-fg` |
| `watch` | Наблюдение | `--watch-*` |
| `abstain` | Не уверена | `--abstain-*` |
| `none` | Норма | `--none-*` |
| `positive` | Позитив | `--positive-*` |

### 3.7 Рамка лица на видео
- Абсолютное позиционирование в процентах от кадра. Подпись над рамкой: «#id · 0,91», при `abstain` — «#id · ?».
- **Цвета:** `alert` — оранжевая сплошная; `none` / `positive` / `watch` — акцент, сплошная; `abstain` — серая пунктирная.

### 3.8 Строка настройки
- Строка минимум 48 px, нижняя граница `--border-row`. Подпись слева (`--text-body`), элемент управления справа.
- **Элементы управления:**
  - **Сегментный переключатель:** кнопки высотой 30 px, выбранная — фон `#26344F` и рамка акцента;
  - **Степпер:** «−», значение моноширинным шрифтом, «+», кнопки 32×32;
  - **Тумблер:** 36×20, квадратный ползунок, включён — фон акцента;
  - **Текстовое поле** высотой 32 px.
- Нативные `<select>` в настройках не используются, вместо них сегментные переключатели.

### 3.9 Раскрывающийся блок
- Заголовок — кнопка на всю ширину с шевроном справа. Шеврон поворачивается на 180° при раскрытии. `aria-expanded`.

## 4. Экран «Потоки»

### 4.1 Состояние А — потоков нет
- Тулбар. По центру рабочей области:
  - иконка камеры в квадрате 72 px;
  - заголовок «Потоков пока нет»;
  - текст: «Добавьте поток с IP-камеры, веб-камеры или по ссылке RTSP / HTTP — распознавание эмоций начнётся сразу после подключения.»;
  - кнопки «Добавить поток» (основная) и «Проанализировать запись» (ведёт в `/analyze`).

### 4.2 Состояние Б — поток выбран
**Боковая колонка (≤ 30% ширины, 260–340 px):**
- Заголовок «Потоки» и кнопка «+».
- Поиск: фильтрует по названию камеры и точки, без учёта регистра, на лету. Пустые группы скрываются.
- Группы по точкам с карточками потоков (§3.3).

**Рабочая область (сверху вниз):**
1. **Плашка инцидента** (§3.4), если у выбранного потока есть неподтверждённый и не скрытый инцидент.
2. **Заголовок:** название потока (22 px) и рамочная метка статуса потока цветом статуса.
3. **Три плитки** (§3.5):
   - **«Клиентов»** — число активных треков;
   - **«Статус»** — «Инцидент», «Не уверена» или «Норма», «—» без сигнала;
   - **«Пригодных кадров»** — проценты.
4. **Ряд «Видео + Посетители»:**
   - **Видео** (flex 4, 16:9, фон `--bg-video`): живой кадр, рамки лиц (§3.7), метка «LIVE» слева сверху. Без сигнала — иконка, «Подключение…» или «Поток недоступен» и кнопка «Переподключить».
   - **«Посетители»** (flex 1, min 260 px), по каждому треку:
     - «Клиент #id» и метка статуса справа;
     - полоса вероятности негатива 6 px (оранжевая — инцидент, серо-синяя — не уверена, акцент — остальное) и число `0,91`;
     - строка «Эмоция · м:сс».

     Все люди в кадре анализируются как клиенты, отдельной роли «сотрудник» нет (см. §10).
5. **«Журнал»**, таблица с колонками: Время (`чч:мм:сс–мм:сс`), Клиентов, Преобладает, Негатив (`0,91`, оранжевым при `alert` / `watch`), Статус (метка). Одна строка на интервал из настроек. Новые строки сверху.
6. **«Камера и обработка»**, раскрывающийся блок (§3.9), по умолчанию свёрнут. Внутри сетка 4 колонки, пары «подпись / значение» моноширинным шрифтом:
   - Источник;
   - Поиск лиц;
   - Кроп лица;
   - Частота анализа;
   - Медиана лица;
   - Пригодных кадров;
   - Задержка уведомления;
   - Интервал журнала.

   Если медиана лица меньше 56 px — жёлтое предупреждение «Лица мельче 56 px: точность снижается. Камеру лучше разместить ближе к зоне обслуживания.» Внизу ссылка «Настройки камеры».

## 5. Экран «Настройки»

Тулбар. Слева вертикальная навигация по вкладкам: строки высотой 40 px, активная — фон `--bg-panel` и `inset 2px 0 0 accent`. Справа содержимое вкладки и внизу кнопки «Отмена» / «Сохранить».

### 5.1 Уведомления
| Строка | Элемент | По умолчанию | Диапазон |
|---|---|---|---|
| Негативные эмоции | мультивыбор-чипы (выбранные — оранжевые) | Злость, Грусть, Страх, Отвращение | + Презрение |
| Допустимая доля ложных | степпер, шаг 5 | 15 % | 5–30 % |
| Эпизод не короче | степпер, шаг 5 | 20 с | 5–120 с |
| Уведомлений на точку в час | степпер, шаг 1 | ≤ 2 | 1–10 |
| Подтверждение получателем | тумблер | вкл. | — |

«Допустимая доля ложных» — это α для автоматической (конформной) калибровки порога на бэкенде. Порог в процентах пользователю не показывается.

### 5.2 Получатели
- Только люди, которых уведомляют о негативных эмоциях.
- Строка получателя: имя, затем мелко «канал · контакт · точки», справа тумблер «уведомлять» и кнопка удаления.
- Строка добавления: Имя, Канал (Telegram / SMS / Email / Push / Тикет), Контакт, Точки (Все точки / конкретная точка), кнопка «Добавить». Без имени добавление не выполняется.

### 5.3 Камеры
- Заголовок и поле поиска (по названию, точке, адресу).
- Строка «Все камеры» с чекбоксом и счётчиком выбранных, справа кнопка «Настроить выбранные» (неактивна, если ничего не выбрано).
- **Панель массовой настройки** (под кнопкой, рамка акцента, тень). В ней те же строки, что у камеры, но:
  - изначально ничего не выбрано, повторный клик по выбранному варианту снимает выбор;
  - невыбранное поле не меняется у камер;
  - кнопки «Отмена» и «Применить» (активна, если выбрано хотя бы одно поле и хотя бы одна камера).
- **Список камер.** Строка: чекбокс, затем кнопка раскрытия «Название · точка», сводка моноширинным шрифтом («Авто · 5 к/с» или «выключен») и шеврон. Выбранная — `inset 2px 0 0 accent`, раскрытая — фон `--bg-panel-alt`.
- **Раскрытая камера.** Строки:

| Настройка | Варианты | По умолчанию |
|---|---|---|
| Анализ | тумблер | вкл. |
| Поток для поиска лиц | Субпоток · Основной | Субпоток |
| Размер кадра для поиска | Авто · 384 · 640 · 960 · 1280 · Тайлы 2×2 | Авто |
| Кроп лица | 160×160 · 224×224 · 260×260 | 224×224 |
| Частота анализа | 3 · 5 · 8 к/с | 5 к/с |
| Мин. размер лица | 40 · 48 · 56 · 64 px | 56 px |
| Мин. резкость | Низкая · Средняя · Высокая | Средняя |
| Макс. поворот головы | 30° · 45° · 60° | 45° |
| Поворот кадра | 0° · 90° · 180° · 270° | 0° |
| Адрес потока | текстовое поле | — |

### 5.4 Журнал и данные
| Строка | Варианты | По умолчанию |
|---|---|---|
| Интервал записи журнала | 5 · 10 · 30 · 60 с | 10 с |
| Хранить журнал | 30 · 90 · 180 · 365 дней | 90 дней |
| Видеофрагмент инцидента | Не хранить · 24 ч · 72 ч | 72 ч |

Интервал журнала задаётся только здесь. Журнал на экране потока его использует.

## 6. Экран «Анализ видео»

Сценарий: пользователь зашёл на сайт, загрузил запись и получил результат распознавания. Разметку он не загружает.

**Боковая колонка:**
- Заголовок «Записи».
- Зона загрузки: пунктирная рамка, иконка, «Перетащите видео сюда», кнопка «Выбрать файлы», форматы MP4, AVI, MOV, MKV. Поддерживаются drag-and-drop и множественный выбор.
- Параметры анализа (четыре селекта 2×2): частота анализа, мин. размер лица, доля ложных, эпизод не короче. Значения по умолчанию берутся из настроек.
- **Очередь файлов.** Карточка файла: имя (обрезается), «мм:сс · разрешение», статус справа (Готово — зелёный, Обработка N % — жёлтый, В очереди — серый), при обработке полоса прогресса 4 px. Активная карточка выделяется как в §3.3.

**Рабочая область:**
- **Готовый файл:**
  1. **Заголовок:** имя файла, строка параметров анализа, справа кнопка «Экспорт» с выпадающим меню:
     - «События и эпизоды» — JSON;
     - «Таблица эпизодов» — CSV;
     - «Видео с рамками лиц и эмоциями» — MP4.
  2. **Три плитки:** «Инцидентов» (с подписью «из N эпизодов»), «Не уверена», «Пригодных кадров».
  3. **Шкала времени**, полоса высотой 36 px:
     - серые отрезки — нет лиц в кадре;
     - кнопки-отрезки эпизодов: оранжевые — инцидент, серо-синие — не уверена;
     - выбранный эпизод — белая рамка и тень;
     - под полосой 5 меток времени, над ней легенда.
  4. **Таблица эпизодов:** Время (`мм:сс–мм:сс`), Клиент (`#id`), Преобладает, Негатив, Статус. Клик по отрезку на шкале выделяет строку, и наоборот (в реализации стоит добавить и это).
- **Файл в обработке или в очереди:** по центру «Обработка: N %» или «Запись в очереди», полоса прогресса, «Результат появится здесь после обработки».

## 7. Модель данных (TypeScript)

```ts
type StreamStatus = 'live' | 'connecting' | 'offline';
type Decision = 'alert' | 'watch' | 'abstain' | 'none' | 'positive';
type Emotion = 'neutral' | 'happiness' | 'surprise' | 'sadness' | 'anger' | 'fear' | 'disgust' | 'contempt';

interface Site { id: string; name: string; }

interface Stream {
  id: string;
  siteId: string;
  name: string;
  status: StreamStatus;
  url: string;                 // rtsp://… | http://… | webcam://0
  sourceResolution: string;    // "3840×2160"
  currentDecision: 'alert' | 'abstain' | 'none' | null;
  usableFramesPct: number;     // 0–100
  medianFacePx: number;
  eventToAlertSec: number;     // p95
  hasOpenIncident: boolean;
}

interface Track {             // посетитель в кадре
  id: number;
  streamId: string;
  negativeProb: number;        // 0–1
  decision: Decision;
  dominantEmotion: Emotion;
  durationSec: number;
  bbox: { x: number; y: number; w: number; h: number }; // доли кадра 0–1
}

interface LogEntry {           // одна запись за интервал
  streamId: string;
  from: string; to: string;    // ISO
  clients: number;
  dominantEmotion: Emotion;
  negativeProb: number;
  decision: Decision;
}

interface Incident {
  id: string;
  streamId: string;
  trackId: number;
  startedAt: string;
  durationSec: number;
  negativeProb: number;
  state: 'new' | 'confirmed' | 'false_alarm';
}

interface Recipient {
  id: string;
  name: string;
  channel: 'telegram' | 'sms' | 'email' | 'push' | 'ticket';
  contact: string;
  siteIds: string[] | 'all';
  enabled: boolean;
}

interface NotificationSettings {
  negativeEmotions: Emotion[];
  maxFalseRatePct: number;     // α, 5–30
  minEpisodeSec: number;       // 5–120
  maxPerSitePerHour: number;   // 1–10
  requireConfirmation: boolean;
}

interface CameraSettings {
  streamId: string;
  enabled: boolean;
  detectionSource: 'substream' | 'main';
  detectionSize: 'auto' | 384 | 640 | 960 | 1280 | 'tiles2x2';
  faceCrop: 160 | 224 | 260;
  analysisFps: 3 | 5 | 8;
  minFacePx: 40 | 48 | 56 | 64;
  minSharpness: 'low' | 'medium' | 'high';
  maxHeadPoseDeg: 30 | 45 | 60;
  rotationDeg: 0 | 90 | 180 | 270;
}

interface LogSettings {
  intervalSec: 5 | 10 | 30 | 60;
  retentionDays: 30 | 90 | 180 | 365;
  incidentClipHours: 0 | 24 | 72;
}

interface VideoJob {
  id: string;
  fileName: string;
  durationSec: number;
  resolution: string;
  status: 'queued' | 'processing' | 'done' | 'failed';

  params: { analysisFps: number; minFacePx: number; maxFalseRatePct: number; minEpisodeSec: number };
```

## 8. Поведение и правила

- **Решение по эпизоду, не по кадру.** Статус трека и журнала вычисляет бэкенд, UI только отображает.
- **«Не уверена»** (`abstain`) — легальный исход, а не ошибка: мелкое лицо, поворот головы, мало кадров.
- **Инцидент** появляется в колокольчике, на карточке потока и плашкой на экране потока. Счётчик в колокольчике = число инцидентов в состоянии `new`.
- **Обновление в реальном времени** через WebSocket/SSE: треки и рамки (несколько раз в секунду), запись журнала (раз в интервал), новые инциденты, смена статуса потока.
- **Без сигнала** плитки показывают «—», видео — заглушку, «Посетители» — «Нет данных», журнал — «Записей нет».
- **Сохранение настроек** по кнопке «Сохранить». «Отмена» откатывает несохранённые изменения. При уходе со страницы с несохранёнными изменениями — подтверждение.
- **Ошибки сети и API** показываются ненавязчиво (toast или строка в блоке), без модальных окон.

## 9. Чего нет в макете (сделать по аналогии)

- **Модальное окно «Добавить поток»:** название, точка, адрес (RTSP / HTTP / веб-камера), проверка подключения, сохранение.
- **Страница «История → Журнал / Инциденты»:** таблица с фильтрами по точке, камере, периоду и статусу, экспорт.
- **«Управление потоками»** (переименование, удаление).
- **Авторизация и роли пользователей.**
- **Состояния загрузки** (скелетоны) и ошибки загрузки файла (неверный формат, слишком большой).

## 10. Открытые вопросы

- **Анализ сотрудников.** В интерфейсе все люди в кадре анализируются как клиенты. В описании проекта это запрещено (EU AI Act, ст. 5(1)(f), критерий «0 вызовов FER для staff»). Нужно решение юриста; если понадобится, вернуть зону сотрудников в настройки камер.
- **Видео с рамками (MP4) содержит изображения лиц.** Стоит удалять файл с сервера после скачивания и логировать экспорт.
- **Демо-данные.** Все числа, имена камер, точки, адреса и `[@контакт]` в макете — заглушки.
