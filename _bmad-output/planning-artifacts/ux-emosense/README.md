# EmoSense — пакет для реализации интерфейса

Всё, что нужно LLM или разработчику, чтобы реализовать веб-интерфейс по макету.

| Файл | Что внутри | Когда давать LLM |
|---|---|---|
| `SPEC.md` | Экраны, переходы, компоненты, модель данных, правила поведения, открытые вопросы, критерии приёмки | Всегда |
| `tokens.css` / `tokens.json` | Цвета, шрифты, отступы, тени, размеры | Всегда |
| `API.md` | REST-эндпоинты и события WebSocket | Когда подключаете данные или пишете бэкенд |
| `mockups/*.dc.html` | Исходники макета — визуальный эталон | Файл того экрана, который делаете сейчас |
| `mockups/FORMAT.md` | Как читать служебный синтаксис макета | Вместе с файлами макета |

Скриншоты в пакет не входят. При желании снимите их в режиме просмотра макета: каждый экран и ключевые состояния (открытое меню, плашка инцидента, раскрытая камера, массовая настройка, меню экспорта).

## Рекомендуемый порядок работы

Давайте задачи по одной и проверяйте каждую по критериям из `SPEC.md` §11.

1. **Каркас:** проект, роутинг, `tokens.css`, тулбар с выпадающими меню, пустое состояние потоков.
2. **Экран потока** на моковых данных: список с поиском и группами, плитки, видео-заглушка с рамками, «Посетители», журнал, блок «Камера и обработка», плашка инцидента, колокольчик.
3. **Настройки:** четыре вкладки, строки-настройки, массовая настройка камер.
4. **Анализ видео:** загрузка, очередь, результат, экспорт.
5. **Подключение к API и WebSocket** по `API.md`.
6. **Экраны из §9 SPEC** (добавление потока, история и т. д.).

## Шаблон промпта

```
Ты — senior frontend-разработчик. Реализуй веб-интерфейс EmoSense.

Стек: React 18 + TypeScript + Vite, React Router, CSS-модули (или Tailwind) поверх tokens.css. Без UI-китов.

Источники:
- SPEC.md — главный документ: экраны, поведение, модель данных, критерии приёмки.
- tokens.css — единственный источник цветов, шрифтов, отступов и теней.
- mockups/<Экран>.dc.html — визуальный эталон; синтаксис объяснён в mockups/FORMAT.md, его не копируй.
- API.md — контракт данных; пока используй моковые данные той же формы.

Задача сейчас: <шаг из порядка работы, например «Шаг 2 — экран потока»>.

Правила:
- Сначала пришли план: дерево компонентов, файлы, состояния. Код — после моего «ок».
- Соблюдай: border-radius 0, тени только у выпадающих меню и активных элементов, тулбар 44 px, список потоков ≤ 30 % ширины.
- Тексты интерфейса — дословно из SPEC.md и макета.
- По завершении пройди чек-лист SPEC.md §11 для этого экрана и отметь, что выполнено.
```

## Важно до начала

Прочитайте `SPEC.md` §10 «Открытые вопросы». Решение анализировать всех людей в кадре, включая сотрудников, противоречит юридическим ограничениям из описания проекта. Его нужно согласовать до реализации.
